## Frequency-dependent materials

The Material Library supports isotropic frequency-dependent relative permittivity (`er`) and relative permeability (`ur`). For either property, enter frequency samples in GHz with real and imaginary values. The EMERGE 3.x Python exporter interpolates the complex values linearly between samples. Frequencies below the first sample use its value; frequencies above the last sample use the last value. The simulation sweep is not restricted to the material's sample range. This export requires EMERGE 3.0.0 or later. The legacy EMERGE v2.x text exporter remains scalar-valued.

## IPC-2581B board import

Use **File → Import IPC-2581B Board JSON (Simulation Model)…** to load clipped `Board.to_dict()` JSON from the standalone `ipc2581_pcb` importer. In that app, open the IPC-2581 XML, inspect the 2D canvas, select nets/layers, draw and apply an AOI, then save/export JSON. The Modeler does not parse raw IPC-2581 XML or perform 2D clipping; it imports validated copper and dielectric geometry as simulation objects. Copper profiles, including explicit interior cutouts, are retained for native BREP STEP export. The standalone importer reconciles rounded arc centers only when the correction fits the source center's decimal precision, retaining the original value as `source_center`; the Modeler allows only a small fallback correction (up to 1% of the radius, subject to preview tolerance) for older JSON. Larger inconsistencies are rejected. Pads require explicit placement, layer, pad-use, dimensions, and supported transforms. `ANTIPAD` definitions are subtracted from other nets' copper on the corresponding layer. Drilled features require an explicit diameter, plating status, and span. If the board contains plated vias, the import requests one positive copper plating thickness in mm and applies it to all plated vias; cancelling the dialog aborts import. This supplies the barrel thickness absent from board JSON and allows the importer to create closed copper via solids. Unsupported primitive forms and incomplete feature geometry are rejected with a specific error rather than guessed. Verify or assign materials before simulation.

Features on IPC board layers explicitly classified as non-copper (such as `DOCUMENT`, `SILKSCREEN`, `SOLDERMASK`, `PASTEMASK`, and `ASSEMBLY`) are omitted from the copper preview. Drill-layer via features are retained so their conductor padstacks and drill geometry can be rendered. Conductive features whose layers are missing from the selected stackup remain an error.

## Important simulation limitations

When importing an IPC-2581B simulation model, choose the number of linear segments per full circle (6–1000). This controls arc, circle, pad, drill, and rounded-track tessellation in the imported STEP profiles; the default is the current **Curved boundary segments** setting. Fewer segments can substantially reduce STEP face count, but approximate circles and can affect small lands, clearances, and narrow features.

- Global Periodic boundaries are not supported. PlaneWave is no longer offered as a new port; saved PlaneWave port entries are kept as legacy data and require manual setup as a ScatteredField simulation.
- New projects start with PARDISO selected. The solver selected in a project is saved with that project and restored when it is reopened.
- **Settings → Simulation** includes SPARTA for EMERGE 3.0.0a23 runtimes with the SPARTA backend installed. SPARTA supports the multiprocessing sweep option; verify GPU/backend availability in the Python environment used to run simulations.
- With **CUDSS** selected, **CUDSS precision** can be set to Automatic (EMERGE default), Single, or Double; explicit choices are emitted with `set_precision('single')` or `set_precision('double')` before solver selection. EMERGE 3.0.0a23 SPARTA does not expose that precision API and remains on its GPU single-precision path.
- **Settings → Mesh** can disable curved-boundary meshing in generated EMERGE scripts; when disabled, the script omits the `set_curved_boundary_meshing` call. The segment count remains active for imported STEP profiles.
- **Settings → Mesh → 3D meshing algorithm** selects EMERGE's `Algorithm3D` implementation (Delaunay by default); the choice is saved in application settings and with the project, and generated scripts use the enum member.
- **ScatteredField** is a simulation type, not a port. It supports one incident plane wave per job, EA or SPH angular definitions (EA by default), a frequency sweep, and defaults to propagation toward -Z with E toward +X, 1 W/m² power density, and the global coordinate system (GCS) as phase origin. EA treats theta as elevation; SPH treats theta as the polar angle from +Z, and switching conventions does not convert entered angles. It requires a configured AIR Open Region and cannot be combined with conventional port excitations or global PML boundaries. Old PlaneWave port records are retained but ignored as legacy data; configure the new simulation settings manually. Select a closed MODEL object as the integration surface for each far-field output. The `plot_sf_3d` output displays the relative field (total minus background) as E vectors and real Ey in the 3D domain at the selected frequency; it does not use a far-field integration surface. A dedicated RCS output is not included.
- A selected global PML boundary requires an enabled, explicitly configured PML shell. The default project tree can show PML before such a shell exists; run **Check Simulation** before export/run.
- **Surface Extrusion** creates an open, unthickened sheet from one open or closed sketch contour, or a complete circular edge chain on a body. For a body edge, exit Sketch mode, select the edge in Edge mode and run **Surface Extrusion**; then select the target face. The sweep axis is the profile normal (the sketch-plane normal for a sketch, or the exact BREP-circle normal for a STEP edge); the selected face chooses the normal sign. The extrusion length is the distance from the profile anchor to the nearest intersection of that normal axis with the selected face. On a curved target face, the central normal axis sets the length; the sheet is not trimmed to follow the face, so its end rim remains parallel to its profile. If the axis does not intersect the selected face, the operation reports the miss and allows another face to be picked. The separate **Extrude** command in the Sketch toolbar creates a solid only from a sketch contour. The live, uncapped preview follows the target-face intersection. Closed contours use their area centroid as the anchor and include the closing edge in the stored perimeter; open contours start at their first point and use their path length. STEP-backed circular body edges are resolved to a unique analytic BREP circle, persisted with the feature, tessellated for the viewport preview, and exported as an analytic cylindrical sheet with a coincident base rim. If the exact source edge cannot be resolved uniquely, creation is rejected rather than using an approximate profile or filling a gap. Sketch contours and non-STEP bodies retain their point-based profiles. A null-length or non-finite vector is rejected and the face pick is re-armed. No end caps or thickness are added. EMERGE requires a closed 3D host volume, and the source sheet bounds must fit inside a volume (for example, the AIR region) for meshing. **Check Simulation** rejects sheet-only, open-surface-host, out-of-volume, unsupported/omitted sheet-boundary, and runtimes without the importable EMERGE 3.0.0-or-later STEP surface API. Check Simulation validates inputs and prepares STEP geometry/scripts; it does not run EMERGE meshing or the solver. Every extruded sheet is imported from its open STEP surface geometry, retaining all curved faces rather than flattening it to a Plate. A LumpedPort uses the imported curved surface with W = exact circumference for an exact STEP circle or profile perimeter/path length otherwise, and H = extrusion length; its height vector follows the signed extrusion direction by default, while non-zero Direction_X/Y/Z values override the LumpedPort direction. Existing point-profile sweep objects do not acquire exact source-edge geometry automatically; recreate them from the STEP edge to use this behavior. Script export converts dimensions from scene units to metres once.
- For an open-region object with only one named face, such as a sphere, missing axis-specific boundary faces are mapped to that sole face. Use a consistent non-PML boundary type for boundaries that resolve to it; conflicting types stop the generated simulation script with an explanation.
- A LumpedPort zero direction is rejected by preflight even though the editor tooltip describes inferring the Plate normal. Enter a non-zero direction.
- LumpedPort BREP gaps up to 100 nm are accepted as connected (converted from the project's model units); gaps or edge-only contacts without finite-area common geometry still produce a warning.
- **Check Simulation** is a local preflight, not an EMERGE run and not a guarantee that a requested solver backend is installed.
- The **Check Simulation** report also shows the Python executable and version used by the app, plus whether EMERGE imports in that same runtime and its detected version. Version lookup for script generation reads installed package metadata without importing EMERGE into the UI process; import failures requested by **Check Simulation** are shown in the report. Installing EMERGE into a different Python environment will not change the interpreter used to launch simulations.
- With the verified EMERGE 3.0.0a20 runtime, result loading uses native EMERGE and does not require a separate `emerge_iron` bootstrap.
- **Eigenmode (Beta)** jobs search near the configured **Eigenmode search frequency** for the requested number of natural modes; this frequency is a search target, not a sweep range. The saved simulation type remains `Eigenmode`.
- EMerge stops mesh generation when its bounding-box estimate exceeds 100,000 tetrahedra; this is an early estimate, not a count of an already generated mesh. The global **Allow oversized meshes** option in **Settings → Mesh** and the per-simulation **Allow an oversized EMerge mesh estimate** option are off by default. If either is enabled, the script disables `size_check` before its single mesh-generation call; it does not retry after a failure. Use this only after checking geometry bounds, scale/units, domain size, and highest sweep frequency; disabling the check may require substantial RAM.
- Far-field outputs save field data; use **Generate Plot** on saved results. They are not rendered by the ordinary automatic S-parameter plotting step. ScatteredField far-field outputs require a selected closed MODEL integration object; this surface is used instead of combining all geometry boundaries. The `plot_sf_3d` ScatteredField view also requires saved fields and uses the relative field to show E vectors and real Ey through the domain.
- For an Eigenmode simulation, add an Output Plot of type `eigen_field` and choose the 1-based mode number. **Basic** settings let you choose the field component, real/imaginary/magnitude quantity, and XY/XZ/YZ cut plane; three evenly spaced cuts and automatic resolution are used. **Advanced** settings also let you set cut positions (percentages of the plane-normal axis), spacing in millimeters (0 selects automatic spacing), geometry opacity, and colormap. Cut positions are limited to 24 and the viewer rejects resolutions estimated to exceed two million field samples.
- If S-parameter fitting fails after a successful solve, the raw Touchstone samples are retained and automatic plots fall back to those samples; a fitted Touchstone file is not produced.
- Touchstone exports are stored in the simulation bundle's `Touchstone` folder. Use **Load Touchstone** in an S-parameter chart to open current or previous `.sNp` results; legacy files in the bundle root are organized into that folder when the picker opens.
- **Generate Plot** uses the latest matching saved Touchstone export when available, avoiding a reload of `simdata.emerge`; exports identify the simulation in their filename. New `.sNp` files use GHz and magnitude/angle data and include an EMERGE/EM 3D Modeler metadata header, sweep and mesh settings, and each port's connected object. The generated time in the header and filename is captured when result export begins, after the solver has completed. Older project-only Touchstone names remain supported. If no usable Touchstone export exists, plots fall back to EMERGE result data.
- Cartesian S-parameter, VSWR, and Touchstone charts use PyQtGraph for interactive zoom/pan, X/Y linear or logarithmic scales, automatic/manual ranges, and movable measurement markers. Smith and 2D far-field charts retain the EMERGE/Matplotlib renderer; 3D far-field plots open in EMERGE's separate interactive window. The 3D normE surface uses a 40 dB range below the peak for its radius, while its color scale retains absolute dBV/m values.
- Chart display modes, axis and marker/legend sizing, and per-trace styles are retained per chart. Datasets added with **Append** or **Load Touchstone** are restored when the chart is reopened. For configured S-parameter outputs, restored datasets show only the S-parameters selected in that output's settings.
- In chart **Settings → Equation**, create an equation with a result name and formula. Select a source parameter (shown as dataset and parameter), assign it a variable name, and optionally add named finite numeric constants. Formulas support numeric literals, parentheses, `pi`, `e`, unary `+`/`-`, and `+`, `-`, `*`, `/`, `//`, `%`, and `**`. Whitelisted functions are `abs`, `angle`, `arccos`, `arcsin`, `arctan`, `conj`, `cos`, `exp`, `imag`, `log`, `log10`, `maximum`, `minimum`, `real`, `sin`, `sqrt`, and `tan`. Variables refer to raw source values (including complex values); the chart's active display mode transforms the calculated result. Combined variables must share the same X values; scalar results are broadcast across that grid. Formula and calculation errors are shown in the Equation tab, and invalid results are not plotted. Calculated traces appear in the **Equations** dataset. Equations, constants, and source bindings are saved per chart and recalculated when chart data changes or is reloaded.
- To unload a dataset you added to a chart, choose it in the dataset selector under **Settings → Available parameters**, then click **Remove dataset**. This removes all its traces and the chart's cached copy, but does not delete the source file or the chart's original data. Equations that referenced the removed dataset remain saved and show a missing-source error until that dataset is loaded again.
- Progressive S-parameter plotting is enabled per Sweep or Parametric job with **Enable progressive S-parameter plotting**; **Update every N points** sets the chunk size (default 10). Sweep jobs stream chunks while reusing one mesh; Parametric jobs stream the nested frequency sweep separately for each parameter value. To see live results, set the linked Output's **Plot timing** to **Live (progressive S-parameters)**. At least one port and the EMERGE 3.0.0 API or later are required; older or unrecognized versions fail closed when this option is enabled. The generated Python integration targets the EMERGE 3.0.0 API baseline; the separate legacy text exporter remains intended for v2.x scripts.
- Adaptive mesh refinement can be enabled per **Sweep** in **Project Tree → Simulation → Edit Simulation**. Enter a passband frequency in GHz within the configured sweep range; choose a frequency where the model is expected to operate, preferably near its resonance, rather than an off-band value. The generated script calls EMERGE's `adaptive_mesh_refinement(frequency=...)` before the sweep (the API receives Hz); refinement adds solver passes and can increase runtime and mesh size. It is disabled by default and is not currently available for other simulation types.
- Generated Python simulations explicitly select `store_system='msgpack'`, matching the EMERGE 3.0 runtime default rather than relying on a version-dependent constructor default.
- Cartesian S-parameter, VSWR, and Touchstone plots use PyQtGraph with display transforms, linear/log axes, manual/automatic ranges, zoom/pan, and movable frequency markers. Smith and 2D far-field plots use the EMERGE/Matplotlib renderer; 3D far-field plots open in EMERGE's separate interactive window. The renderer is selected by plot type rather than a global graphics-mode switch.
- For a closed waveguide, an AIR containment error can indicate that open-region boundaries are enabled for an internal-air/PEC-wall model. Review the domain and boundary setup before changing geometry.

To regenerate the embedded sketch toolbar screenshot by itself, run `python scripts/capture_help_screenshots.py --sketch-toolbar-only`. Other screenshot instructions are in [SNAPSHOT_CAPTURE.md](SNAPSHOT_CAPTURE.md).

## Mesh settings

In **Settings → Mesh**, choose a 3D meshing algorithm: **Delaunay** (the backward-compatible default), **Initial mesh only**, **Frontal**, **MMG3D**, **R-tree**, or **HXT**. The selection is stored in application preferences and the active project; generated main and clean/worker scripts call `simulationObj.mesher.set_algorithm(em.Algorithm3D.<choice>)`.

**Save mesh after a successful sweep** is off by default. When enabled, generated Sweep and Parametric scripts export the active EMERGE mesh as a simulation-specific `.msh` file in that run's results folder after the sweep completes. If the preferred filename already exists, the script uses the next available numbered filename rather than replacing it. Eigenmode jobs and scripts that do not run a sweep do not export a mesh.

Adaptive mesh refinement is configured separately for each Sweep job in its simulation editor. It is disabled by default.

## Utility settings and Boolean mesh simplification

In **Settings → Utility**, **Export complete scene STEP** enables a separate full-scene STEP export. Enabling it marks that export for the next simulation preparation; it does not force a re-export of the ordinary per-object STEP bundle when that bundle is already current.

**Ask for mesh decimation on Fuse, Cut and Intersect** is off by default. When off, Boolean commands do not prompt and use 0% reduction. When on, each Fuse, Cut or Common (intersection) command asks for a target triangle reduction from 0% to 80% in 5% steps. A non-zero value simplifies the resulting mesh, is saved with the Boolean result, and is reapplied when that result is recomputed. STEP export uses the stored simplified mesh rather than rebuilding the exact source BREP. Simplification can change dimensions and small features; inspect clearances, via connections, and port contact before simulation. The target is a reduction request, so topology-preserving decimation may achieve less on difficult meshes.

## Boolean Cut

The **Configure Boolean Cut** dialog places the first selected object in **Objects to cut (Base)** and the remaining selected objects in **Cutting tools (Tools)**. Both lists support multi-selection. Select one or more rows and use the right arrow to move them from Base to Tools, or the left arrow to move them from Tools to Base. At least one object must remain in each list. Every Base is cut by all Tools and produces its own result. **Keep cutting tools in project** is unchecked by default: leave it unchecked to remove the Tools after the operation, or check it to retain them. Choose **OK** to run the Cut or **Cancel** to leave the scene unchanged.
